# Proposal: four folders

© 2026 Casey Houle. All rights reserved.

Status: proposal, 2026-09-20. Nothing has been moved. The costs of moving are
listed at the end so the decision is made with them in view.

The rule: every file the engine owns or produces sits in exactly one of four
folders, and the folder's name says what kind of thing it is, so a user who has
never read a spec can answer "where do I look?" without help. The four kinds are
the same in both places the engine lives.

| kind | question it answers | mutability |
|---|---|---|
| **rules** | what is the system required to do? | human-authored; changed only through the governance protocol |
| **engine** | what does the checking? | engine-owned code; replaced whole on update, never edited in place |
| **records** | what happened? | append-only; rows are superseded, never edited |
| **work** | what is in flight right now? | transient; safe to delete, regenerated by the next command |

## In a project (`.engine/`)

Today `.engine/` has fourteen entries at its top level. Proposed:

```
.engine/
  rules/      RULES.md, agents/ (reviewer definitions), reference/, config.json,
              control-manifest.json, governance.json, dependency-policy.json,
              catalogues/            ← the whole governed set, and nothing else
  engine/     harness/ (package + run.py + selftest), reviewers/ (drivers, MODELS.md),
              hooks/, VERSION, placed.json, CHANGES.md, DATA.md
  records/    gate-log.md, findings-register.md, governance-changelog.md,
              mutation-results.md, standing-state-deltas.md, started/,
              coverage-inventory.md, undeclared-controls.md, generated-truth.md,
              reconciliation-obligations.md, carried-findings.md, ingest-records.md,
              high-side-changes.md, scan stamps and alarms
  work/       handoff-*.md, gate-*-checklist.md, gate-*.json, verdict-*.json,
              raw-*.json, coverage.json, snapshots/, rules-at-base-*/, bakeoff*/
              (today's `local/`)
```

What a user needs to know collapses to one sentence: *rules are what you
promised, engine is what checks it, records are what it found, work is
scratch.* The project's own files (`src/`, `tests/`, `plans/`, `tickets/`,
`AGENTS.md`) stay where they are — they are not the engine's.

The `.engine-reference` copies (`AGENTS.md.engine-reference`,
`control-manifest.json.engine-reference`, …) move under `engine/reference/`
so the project root and `rules/` hold only live files.

## In the harness repository (`~/engine`)

Today the top level has twenty entries. Proposed:

```
engine/       the package (checks/, records/, scan/, dist/), selftest/, integration/,
              reviewers/ (see the note on the no-network scan below)
rules/        specs/, v1.0.md, ledger.tsv, GOVERNANCE-SET.md, AMENDMENTS.md,
              RELEASE-RECORD.md, PROVENANCE.md, LICENSE, prompts/
records/      .build-log.md, receipts/, LIFECYCLE-EXERCISE.md, STRUCTURE-PROPOSAL.md,
              NEXT-PROMPT.md (the session-to-session record)
work/         tools/ (progress, ledger, receipt scripts and their tests), hooks/
              (the build's own git hooks), drive.sh, budget.txt, .engine/local/
```

`rules/` here is the governance set the pre-commit hook already protects
(`GOVERNANCE = ("v1.0.md", "tools/progress.py", … "specs/", …)`); giving it one
folder makes that tuple a single prefix.

## Costs, in order of size

1. **The ownership map** (`engine/ownership.py`) names every placed path; the
   placed layout change is one table edit plus `update --project` on each
   project, which already preserves prior content beside each diverged file.
   The self-tests that assert placed paths (`test_distribute`, `test_cli`) change
   with it.
2. **Record readers** hard-code `.engine/records/…` in `engine/records/schema.py`
   and `.engine/local/…` in `gate.py`, `handoff.py`, `probes.py`, the reviewer
   drivers and the bake-off. Keep `records/` where it is (it already fits) and
   rename `local/` → `work/`: about thirty string sites, all found by one grep.
3. **The governed-set list** in `.engine/governance.json` and in `hooks/pre-commit.py`
   (build side) changes to the new prefixes; the governance protocol itself
   does not change.
4. **Moving the reviewers under `engine/`** trips the harness's own no-network
   scan (they import `urllib`; that is their job, loopback only). It was tried
   during this session and reverted. Either keep `reviewers/` beside `engine/`
   (five folders in the build tree, four in the placed tree) or give the
   no-network check a declared exemption that the drivers earn by refusing
   every non-loopback endpoint at the top of `main()` — the refusal already
   exists; only the declaration would be new, and it should be a finding to
   remove it.
5. **The evidence export** writes an index over `.engine/records/` and `.engine/local/`;
   the export's paths follow the readers in item 2.

A one-session job with the regression tests the lifecycle exercise established;
it should be done as its own unit with its own gate rows, after v1.0 is
announced, not before.
