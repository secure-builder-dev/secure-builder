04Hardware — laptop vs GB10 (the two-number model)

Every local-LLM box is two numbers: capacity (how big a model fits = memory size) and speed (tokens/sec = memory bandwidth). The GB10 inverts them vs the laptop.

Decode speed (dense) ≈ bandwidth ÷ model-bytes-in-memory. So: for anything ≤24 GB the laptop is faster; for anything bigger the GB10 wins because the laptop can't hold it at all.

05The offload cliff — why "just add RAM" fails

When a model overflows 24 GB VRAM, the rest spills to system RAM and runs on CPU. The pools differ by ~10× — VRAM ~896 GB/s vs laptop DDR5 ~90 GB/s — and speed is set by the slowest pool weighted by how much sits there.

# 70B dense Q4 (~40 GB): 20 GB in VRAM + 20 GB in RAM
time/token ≈ 20/896  +  20/90   =  0.022s  +  0.222s   → ~4 tok/s
             (VRAM 9%)  (RAM 91%)
# half the model offloaded — but that half is 91% of the time

Laptop + 128 GB RAM ≠ GB10 128 GB unified

Adding laptop RAM raises the capacity ceiling, not the speed floor — the moment a model leaves the 24 GB VRAM it runs at ~90 GB/s. The GB10's whole 128 GB runs at 273 GB/s — ~3× faster for the overflow portion. That's the entire value of unified memory: no slow second pool to fall off into.

06eGPU — the surprising part & the size reality

The Thunderbolt link (~32–80 Gbps) is not the decode bottleneck: model weights live on the eGPU's own VRAM and are read at the card's full internal bandwidth. The link only carries the one-time load + tiny per-token activations. What matters is total VRAM across all GPUs. Use layer split (llama.cpp default), never tensor-parallel, across the slow link.

Cheapest route to 70B: your internal 24 GB stacks with an eGPU — CUDA sees both. Internal 24 + eGPU 24 = 48 GB → holds 70B Q4 at ~10–20 tok/s. Used RTX 3090 + enclosure ≈ ~$1,000.

07DDIL field kit — complete air-gap, forward at a unit

The real Track-C target: modify a codebase forward, in a Denied / Degraded / Intermittent / Limited environment, fully air-gapped. Here SWaP, field power, ruggedness, and air-gap simplicity outrank raw speed. Fewer boxes = simpler air-gap.

Complete-airgap controls

  • Kill the radios — wifi/BT/cellular firmware-disabled or physically removed. No RF path.
  • Provision everything at base — OS, models, engine, corpus, repo — hash-verified vs a manifest. Nothing pulled in field.
  • No telemetry / auto-update — Ollama fully offline; verified in a test air-gap first.
  • Data in/out via controlled scanned media only — never a live link.
  • §8 OPSEC on the box — placeholders only, no real infra values (box is physically at risk).

SSH ≠ internet

  • Two boxes join over a direct Ethernet or Thunderbolt cable — static IPs, no switch, no WAN.
  • Traffic is tiny (prompts + verdicts, not weights) — even 1 GbE is overkill.
  • An air-gapped two-box split makes the §3 bias firewall more real: build on laptop, 70B gate on the mini — different hardware, different weights, still offline.

Offline workflow

  1. Provision the kit at base (models + engine + corpus + repo), hash-verified.
  2. Modify code fully offline — local build/gate loop, no connectivity; human runs the §5.5 manual review.
  3. Evidence in local git — TDD two-commit, append-only gate-log, ADRs. Git history = tamper record.
  4. Exfil minimally when a pipe appears — git bundle / format-patch = tiny diff+evidence file, sneakernet or narrow link.
  5. Downstream platform team reviews — the real separation of duties. The kit's gates are pre-flight, not an ATO.

08Honesty — §9 stacks worst forward

Three weaknesses compound here: the local model is weaker at security reasoning · local-attested is the weakest enforcement · forward is where a miss is least recoverable — all at once. The forward air-gapped build needs more human rigor, not the same. If you can carry the mini-PC for a 70B gate, that capability jump is most valuable precisely here. Don't over-quant the gate model to save weight — that trades away the reasoning you deployed it for.

What's machine-verified

  • Nothing about model provenance is. There is no US-gov approved-model whitelist — approval runs via procurement (GSA OneGov, FedRAMP) + a covered-nation prohibition framework.
  • "This origin is acceptable" = a human ratification.
