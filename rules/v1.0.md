# v1.0 — the exit condition

© 2026 Casey Houle. All rights reserved.

Human-owned. In the build's governance set. Never edited by the loop.

The check command is `python -m engine check`.
The progress command is `python tools/progress.py`.

v1.0 is reached when ALL of the following are true, each verified by
`python tools/progress.py`:

1. Every numbered requirement in specs 01-06 and 11 has a ledger row, and every
   row is either
     - done, with a pointer to the implementing file that exists, or
     - defer, with a written reason and a version tag (v1.x), or
     - na, with a written reason.
   Zero rows in state `todo` or `doing`.

2. Every `done` row has a mutation receipt on disk proving the check has been
   observed failing: both sections present, the broken section shows failure,
   the restored section shows success. No receipt, no credit.

3. `python -m engine check` exits 0 from the repository root.

4. The self-test suite runs from `python -m engine check`, reports pass, fail
   and skip counts separately, and its skip count is zero or every skip is
   named below under "Named skips".

5. No ledger row has an `impl` column reading `unknown`.

6. One full lifecycle has been exercised end to end on a throwaway project —
   build -> gate -> finding -> disposition -> record -> close — and
   `records/LIFECYCLE-EXERCISE.md` records the date, the throwaway project path, and
   the gate-log rows it produced. This clause is checked by a person doing it
   once; progress only verifies the record exists and is not a template.

7. The degradation statement (spec 04 §7) is producible by
   `python -m engine degradation` and exits 0.

8. The integration tier (spec 05 §6.1) has either run and passed, or is
   recorded as *not verified in this environment* in `records/RELEASE-RECORD.md`.
   It is never recorded as a pass on the strength of the hermetic tier.
